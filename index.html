About me

I build things to understand them — that's not a method, it's just how I'm wired. If something is interesting enough, the only way I can actually get it is to take it apart and put it back together myself. That's taken me from writing low-level memory systems in Go, to running controlled experiments on distributed ML schedulers, to building security tools that read source code the same way an attacker would. The domain changes; the instinct doesn't.

Right now I'm deep in LLMs — not the API layer, but the actual internals. I'm studying how to build one from scratch: attention mechanisms, tokenization, the training loop, all of it. Alongside that I've been spending time on inference and harness engineering — how you take a raw model and make it reliable, measurable, and fast in production. That gap between "model works in a notebook" and "model works under load" is where I want to live.

Outside of that I swim. It's the one thing that fully empties my head — no tabs open, no threads running. I come back from the pool and the problem I was stuck on usually solves itself.

What I'm chasing

01

LLMs from the inside

Not the API, the actual internals — attention mechanisms, tokenization, the training loop. I want to understand what the model is doing at every step, not just what it returns. Building one from scratch is the only way I know how to do that.

02

Inference & harness engineering

The gap between a model that works in a notebook and one that works under real load. Quantization, batching, latency budgets, reliability under production conditions — making a raw model actually usable is a separate engineering problem, and it's the one I find most interesting right now.

03

Agentic systems that don't lie

I've built enough agents to know where they break — schema drift, hallucinated tool calls, silent failure under ambiguity. The interesting problem is making the failure surface visible and recoverable, not just throwing more context at it.
